Plexus-Flow Developer Documentation

Plexus-Flow is a distributed, Raft-native workflow, DAG, and Saga orchestration engine packaged as a single Go binary. It combines a deterministic Raft consensus state machine (FlowStore), a lease-based distributed task queue (ActivityStore), an in-memory faceted search index, a gRPC remote worker broker, and a real-time Web UI—requiring zero external databases or message brokers.

60-Second Quick Start

Build and start a production single-node server with the embedded HTTP API, Web UI (`:8080`), and gRPC Worker Broker (`:9090`):

bash — Start Production Server
# Build the plexus-flow server binary
go build -o bin/plexus-flow ./cmd/plexus-flow

# Start a single-node server with persistent BoltDB storage and pre-loaded JSON flows
./bin/plexus-flow \
  --id node-1 \
  --http-addr :8080 \
  --grpc-addr :9090 \
  --raft-addr 127.0.0.1:7001 \
  --act-raft-addr 127.0.0.1:7002 \
  --data-dir ./data/node-1

Dual-Raft Graph Architecture & Consensus-Level EOS

Every Plexus-Flow node hosts two coordinated Raft state machines connected by a deterministic bridge:

  • Upstream (FlowStore): Manages workflow definitions, workflow instances, DAG dependency evaluation, conditional branching, timers, signals, cron schedules, and the inverted search index.
  • Downstream (ActivityStore): Manages pending activity tasks, worker leases, heartbeats, retry backoffs, and task completion/failure records.
  • Deterministic Idempotency Key (UpstreamID:Term:Index:Seq): Every task emitted when a Raft log entry commits carries its exact Raft coordinates. If a leader crashes mid-dispatch and the new leader re-evaluates the log, ActivityStore deterministically absorbs the duplicate emission as an O(1) no-op.

Fork-Join DAG Parallelism (depends_on)

Any step with an empty depends_on array starts immediately when the workflow begins. Steps that share the same upstream dependency run concurrently (fan-out), and a step listing multiple dependencies in depends_on waits until all of them reach COMPLETED or SKIPPED (fan-in / join). Cycle detection is enforced at registration time via topological validation.

Conditional Branching (when Predicates)

Before dispatching a step whose dependencies are satisfied, the Raft FSM evaluates its optional when predicate. If it evaluates to false, the step immediately transitions to SKIPPED without dispatching a worker task.

Field Supported Values Description
source "input" (default), "metadata", or "<step-name>" Selects the workflow input JSON, workflow metadata map, or a completed upstream step's output JSON.
field Dot-path (e.g. "metrics.accuracy") or "$status" Extracts nested JSON fields or inspects an upstream step's terminal status ("COMPLETED" vs "SKIPPED").
op eq, ne, gt, gte, lt, lte, in, exists, not_exists Comparison operator applied against value.

Automatic LIFO Saga Compensation

When any step exhausts its retry policy (or fails with a non-retryable error code), the workflow transitions to COMPENSATING. Plexus-Flow walks all previously COMPLETED steps in reverse topological order (LIFO) and dispatches their compensating_action activities with full retry protection until every completed step reaches ROLLED_BACK and the workflow reaches COMPENSATED.

Durable Timers (sleep) & Human-in-the-Loop Gates (wait_for_signal)

  • Durable Sleep Timers: Setting "sleep": "15m" persists a deterministic WakeAt timestamp in the Raft FSM. Even if the entire cluster restarts during the sleep window, the step completes as soon as wall-clock time passes WakeAt.
  • Durable Signal Gates: Setting "wait_for_signal": "approval" pauses the branch in WAITING_SIGNAL (consuming zero worker threads). When POST /api/v1/workflows/{id}/signal arrives (even if buffered before the step was reached!), the signal payload becomes that step's Output JSON.

Building Data-Pipeline-Heavy Platforms

Plexus-Flow includes first-class primitives designed specifically for long-running ETL jobs, distributed batch ingestion, and multi-stage ML training pipelines.

1. Stateful Progress Checkpointing (HeartbeatWithProgress & LastProgress)

Long-running data activities can attach an arbitrary JSON checkpoint payload to every heartbeat. Plexus-Flow replicates this payload into the Raft FSM (`StepState.LastProgress`). If the worker crashes, loses its lease, or the Raft leader fails over, the newly dispatched attempt receives `LastProgress` so it can resume from the exact batch offset or training epoch.

python — Resumable Batch Processing with Checkpoints
@worker.activity("backfill-snowflake-partition")
def backfill_partition(ctx: ActivityContext, job: dict) -> dict:
    # 1. Inspect replicated checkpoint from any prior interrupted attempt
    state = ctx.last_progress or {"cursor_offset": 0, "processed_rows": 0}
    offset = state["cursor_offset"]
    total = state["processed_rows"]

    while offset < job["total_rows"]:
        batch = fetch_rows(job["table"], offset=offset, limit=50_000)
        write_to_warehouse(batch)
        offset += len(batch)
        total += len(batch)

        # 2. Renew worker lease AND commit progress checkpoint to Raft FSM
        ctx.heartbeat_progress({"cursor_offset": offset, "processed_rows": total})

    return {"status": "done", "rows_committed": total}

2. Time-Travel Step Replay (/replay)

In data-heavy pipelines, early stages (like extracting 500 GB from S3 or running an LLM embedding pass) are expensive, while downstream stages (like SQL transformations or schema formatting) may fail due to a code bug. Once you deploy the bug fix to your workers, call Replay on the failed step:

bash — Rewind a Failed Step & Its Downstream Dependents
curl -X POST http://localhost:8080/api/v1/workflows/etl-run-2026-10/replay \
  -H "Content-Type: application/json" \
  -d '{"step": "transform-cleanse"}'
How Time-Travel Replay Works: Plexus-Flow resets transform-cleanse and all of its transitive downstream dependents back to PENDING (clearing their stale errors/outputs), keeps all upstream steps (e.g. extract-raw-events) COMPLETED with their cached outputs, transitions the workflow back to RUNNING, and immediately dispatches transform-cleanse.

3. Selective Retries & Non-Retryable Error Codes

Transient network glitches should retry with exponential backoff, whereas deterministic data errors (e.g., ERR_INVALID_SCHEMA) should fail fast. List terminal error codes in retry_policy.non_retryable_errors and raise a coded error from Go or Python:

go & python — Raising Non-Retryable Error Codes
// Go Worker:
return MyOutput{}, worker.NewCodedError("ERR_INVALID_SCHEMA", fmt.Errorf("missing column: user_id"))

# Python Worker:
from plexus_flow import ActivityError
raise ActivityError("missing column: user_id", code="ERR_INVALID_SCHEMA")

4. Zero-CDC Sub-Millisecond Faceted Search

Every workflow can carry arbitrary metadata key-value tags (`map[string]string`). Plexus-Flow maintains an in-memory inverted index inside `FlowStore` that updates atomically with every Raft transition—giving you sub-millisecond multi-attribute queries without Elasticsearch:

bash — Multi-Attribute Faceted Search
# Find all FAILED workflows for tenant=acme in region=eu-west-1
curl "http://localhost:8080/api/v1/workflows?status=FAILED&name=data-lake-ingestion-pipeline&meta.tenant=acme&meta.region=eu-west-1&limit=50"

Go SDK & Embedded Engine Reference

Plexus-Flow can be used either as a standalone cluster connected via gRPC workers (`pkg/workerclient`) or embedded directly inside your Go services (`pkg/graphflow`).

Type-Safe Generic Workers & Multi-Node Failover

go — Typed Worker Registration & Cluster Failover
package main

import (
    "context"
    "log"
    "github.com/avivklas/plexus-flow/pkg/worker"
    "github.com/avivklas/plexus-flow/pkg/workerclient"
)

type TransformInput struct {
    DatasetURI string \`json:"dataset_uri"\`
    BatchSize  int    \`json:"batch_size"\`
}

type TransformOutput struct {
    RowsWritten int    \`json:"rows_written"\`
    TableURI    string \`json:"table_uri"\`
}

func main() {
    reg := worker.NewRegistry()

    worker.RegisterTyped(reg, "spark.cleanse", func(ctx context.Context, in TransformInput) (TransformOutput, error) {
        // Read previous checkpoint if resuming after a crash
        lastCheckpoint := worker.LastProgressFromContext(ctx)
        _ = lastCheckpoint

        // Stream live progress back to Raft
        reportProgress := worker.ProgressFromContext(ctx)
        _ = reportProgress([]byte(\`{"stage": "deduplicating", "pct": 75}\`))

        return TransformOutput{
            RowsWritten: 250000,
            TableURI:    "s3://curated/clean.parquet",
        }, nil
    })

    // Pass comma-separated cluster addresses (or Options.Addresses) for automatic leader discovery & failover
    client := workerclient.New("10.0.0.1:9090,10.0.0.2:9090,10.0.0.3:9090", reg, workerclient.Options{
        WorkerID:    "go-etl-worker-01",
        Concurrency: 16,
    })

    if err := client.Run(context.Background()); err != nil {
        log.Fatal(err)
    }
}

Horizontal Partitioning with ShardedCoordinator

For ultra-high-throughput in-process workloads, graphflow.ShardedCoordinator partitions workflows across N independent Dual-Raft shard pairs using deterministic FNV-1a hashing (`shard = fnv1a(workflowID) % numShards`), scaling write throughput linearly while aggregating search and SSE streams across all shards.

Python Worker & Client SDK Reference

Install the Python SDK from the repository (`pip install -e sdk/python`):

python — Full Worker & WorkflowClient Usage
from plexus_flow import Worker, ActivityContext, ActivityError, WorkflowClient

# 1. Define Activities on a gRPC Worker
worker = Worker("localhost:9090", worker_id="py-ml-worker", concurrency=4)

@worker.activity("gpu.embed_chunks")
def embed_chunks(ctx: ActivityContext, payload: dict) -> dict:
    if not payload.get("dataset_uri"):
        raise ActivityError("dataset_uri is required", code="ERR_INVALID_INPUT")

    ctx.heartbeat_progress({"batches_completed": 5, "total_batches": 10})
    return {"vector_count": 128_000, "dimension": 1536}

# Run worker in background thread or main process:
# worker.run()

# 2. Orchestrate Workflows via HTTP/SSE Client
client = WorkflowClient("http://localhost:8080")

wf = client.start_workflow(
    "data-lake-ingestion-pipeline",
    {"dataset_uri": "s3://raw/events.parquet", "enable_embeddings": True},
    workflow_id="ingest-job-42",
    metadata={"tenant": "acme", "pipeline": "embeddings"}
)

# Stream real-time state updates over Server-Sent Events (SSE)
for snapshot in client.watch("ingest-job-42", timeout=60.0):
    print("Status:", snapshot["status"])
    if snapshot["status"] in ("COMPLETED", "FAILED", "COMPENSATED"):
        break

HTTP REST & Real-Time SSE API Reference

Every node exposes the full HTTP API. Follower nodes transparently proxy mutating requests (`POST`, `DELETE`) to the active Raft leader.

Method & Path Description
POST /api/v1/definitions Register or update a declarative WorkflowDefinition JSON schema.
GET /api/v1/definitions List all registered workflow definitions.
POST /api/v1/workflows Start a new workflow execution (accepts id, workflow_name, input, metadata).
GET /api/v1/workflows Search & paginate workflows (`?status=RUNNING&name=...&meta.key=val&offset=0&limit=50`).
GET /api/v1/workflows/{id} Inspect a workflow instance, including per-step status, outputs, attempts, and `last_progress` checkpoints (transparently falls back to `ColdArchive` if compacted).
POST /api/v1/workflows/{id}/signal Deliver a named external signal (`{"signal": "...", "payload": {...}}`) to a waiting workflow.
POST /api/v1/workflows/{id}/replay Time-Travel Replay: Rewind a failed step (`{"step": "..."}`) and its downstream dependents while keeping upstream outputs intact.
POST /api/v1/workflows/{id}/cancel Cancel an active workflow execution.
GET /api/v1/workflows/{id}/events Subscribe to a real-time Server-Sent Events (`text/event-stream`) stream for a specific workflow.
GET /api/v1/events Subscribe to the global Server-Sent Events firehose for all workflow transitions.
POST /api/v1/schedules Create or update a durable cron schedule (`id`, `workflow_name`, `cron`, `timezone`, `overlap_policy`).
POST /api/v1/schedules/{id}/pause Pause a cron schedule (`/resume` to resume, `DELETE /api/v1/schedules/{id}` to delete).
GET /api/v1/cluster/status Inspect Raft leadership (`is_leader`, `leader_id`, `leader_addr`), connected gRPC workers, and in-flight leases.
POST /api/v1/admin/compact Manually trigger retention compaction (`{"older_than": "24h", "max_keep": 10000}`).
GET /healthz & GET /readyz Kubernetes liveness (`200 OK`) and readiness (`200 OK` when Raft quorum has an elected leader) probes.

Production Multi-Node Raft Clustering

Deploying a fault-tolerant 3-node (or 5-node) cluster requires zero external coordination services. Boot `node-1` as the initial cluster leader, and point `node-2` and `node-3` at `node-1` via `--join` and `--act-join`:

bash — Booting a 3-Node Fault-Tolerant Cluster
# Node 1 (Bootstrap Leader)
plexus-flow \
  --id node-1 \
  --http-addr 0.0.0.0:8081 \
  --grpc-addr 0.0.0.0:9091 \
  --raft-addr 127.0.0.1:7001 \
  --act-raft-addr 127.0.0.1:7002 \
  --data-dir /var/lib/plexus-flow/node-1

# Node 2 (Voter — auto-joins Node 1)
plexus-flow \
  --id node-2 \
  --http-addr 0.0.0.0:8082 \
  --grpc-addr 0.0.0.0:9092 \
  --raft-addr 127.0.0.1:7003 \
  --act-raft-addr 127.0.0.1:7004 \
  --join 127.0.0.1:7001 \
  --act-join 127.0.0.1:7002 \
  --data-dir /var/lib/plexus-flow/node-2

# Node 3 (Voter — auto-joins Node 1)
plexus-flow \
  --id node-3 \
  --http-addr 0.0.0.0:8083 \
  --grpc-addr 0.0.0.0:9093 \
  --raft-addr 127.0.0.1:7005 \
  --act-raft-addr 127.0.0.1:7006 \
  --join 127.0.0.1:7001 \
  --act-join 127.0.0.1:7002 \
  --data-dir /var/lib/plexus-flow/node-3

Tiered Storage & Cold Archival (ColdArchive)

To keep hot Raft memory bounded indefinitely while preserving historical audit trails, configure `--retention-ttl` (or `CoordinatorConfig.ColdArchive`). Before `CompactWorkflows` purges terminal workflows from the Raft FSM, it archives them to your `ColdArchive` backend (such as `flowstore.MemoryArchive`, SQLite, S3, or object storage), and `GetWorkflow` transparently falls back to cold storage on a hot-cache miss.
